## 1. 電視瘦身方案

**結論：不用 debloat 工具，用 adb `pm disable-user --user 0` 小批停用，每批先記錄原始狀態、只還原本批改過的。Projectivy 先不裝。**

| 項目 | 判斷 | 證據 |
|---|---|---|
| 停用 vs 解除安裝 | 一律 `disable-user`；不用 `uninstall --user 0`、不 root | 文件（UAD-NG FAQ，R2／R2b 核對相符） |
| 能改善多少 | 同平台（client type TCL-AP-RT2851-S1，韌體 V674）50J7000A 停 25 套件：MemAvailable 約 495→655 MB，重開後維持、HDMI／串流正常 | 文件（同平台他機型）；本機（V715）待驗 |
| 換桌面（Projectivy） | 推薦／促銷／遙測是獨立套件，換桌面不會停掉；新款 TCL 有搶回 HOME 回報 | 文件（機制）；省 RAM 幅度無量化數據 |
| 語音熱詞 katniss | BeyondTV4 個案：常駐約 28% 單核，撤麥克風權限降到 0.4%；代價是語音失效 | 文件（他機型個案）；本機待驗 |
| 卡頓原因 | 記憶體壓力、/data 空間、eMMC 老化、背景服務都有可能，**先量再動** | 文件（Android TV 記憶體指南）；本機待驗 |
| 首頁只留五個 App | 停用推薦／促銷套件不保證首頁乾淨；換桌面（Projectivy）是達成此目標最直接的方法，排在第一批停用之後（步驟 3b） | 待驗 |
| 工具 | UAD-NG：可選 GUI；CleanYourTV：同平台清單與做法當參考；android-tv-debloat-toolkit：不用（無備份、清單含 Netflix） | 文件 |

**第一批候選線索**（R2、R2b 都說可停，且同平台兩份清單都停過）：`com.tcl.bi`、`com.google.android.feedback`、`com.google.android.partnersetup`、`com.tcl.overseasappshow`、`com.tcl.tv.tclhome_passive`、`com.tcl.waterfall.overseas`、`com.tcl.messagebox`、`com.tcl.esticker`、`com.tcl.copydatatotv`、`com.tcl.notereminder`、`com.google.android.tvrecommendations`。
本機要「有這個套件＋確認功能＋家人不需要」三項都成立才停；用途不明的不動。預載遊戲／串流不在第一批。

**保留不動**（保守決策，證據強度不同）：
- 同平台清單一致列禁區：`com.tcl.tv`、`com.tcl.tvinput`、`com.tcl.tvpassthrough`、`com.tcl.keycustomfunctionservice`、`com.tcl.partnercustomizer`、`com.tcl.settings`、`com.tcl.initsetup`、`com.tcl.factory.view`、`com.tcl.inputmethod.*`、`com.tcl.autopair`、`xian.StartandroidService`、`com.tcl.versionUpdateApp`。
- 預防性保留（無 TCL 災情證據）：`com.google.android.gms`、`com.android.vending`、`com.google.android.apps.mediashell`、`com.google.android.tv.remote.service`、Wi-Fi／藍牙／Widevine／DRM 相關。
- 跨機型推論或名稱未確認：`com.google.android.tungsten.setupwraith`（災情為 Sony 機）、`com.tcl.systemserver`／`com.tcl.system.server`（是否同一套件未確認）。
- 有爭議，第一批不碰：`com.tcl.guard`、`com.tcl.usercenter`、`com.tcl.tvweishi`、`com.tcl.appmarket2`、`com.tcl.dashboard`。

**還原原則**
- 每批停用前記錄該批每個套件的原始狀態（`pm list packages -d` 全量＋該批清單）；還原只把本批「由啟用改為停用」的套件 `pm enable`，原本就停用的不動。
- 每批停用後先確認重開機後 adb 仍可連、遙控器可回首頁，才做下一批；確認不了就停止並回報，不假設之後還能操作。
- OTA 後停用套件可能復活（文件）：先重新盤點、確認清單仍適用，再決定是否重做。
- 恢復原廠**不列為還原手段**（他機型有 NVM reset 弄丟 Widevine／Netflix ESN 案例），只作最後手段且須 Owner 同意。
- 瘦身後仍卡：外接電視盒（Google TV Streamer 台灣建議售價 NT$3,250，媒體報導），電視只當顯示器。

## 2. 時間管理方案

**結論：採方案 C（Linux 小主機＋adb＋小服務＋iPhone 捷徑）。不用 Home Assistant、不訂閱、不開發電視 App。**

### 運作方式（設計目標，本機待驗）
服務只記一個值：**到期時間**，以「寫暫存檔再改名」的方式安全寫入；檔案不存在或讀不到 → 視為未授權。
- iPhone 捷徑（POST，token 放 HTTP header，不放網址）：開放 15／30／60 分鐘、立即鎖、查狀態。
- 開放：到期時間＝現在＋N 分鐘 → 立即啟用 YouTube → **確認實際啟用成功才回「可以看」**，失敗回原因（倒數照樣從核准時開始）。授權中再按開放＝家長重新核准，以新的到期時間為準。
- 立即鎖：到期時間清空 → force-stop＋停用，優先於其他請求。
- 到期：服務準時執行 `am force-stop`＋`pm disable-user`（YouTube，與本機若有的 YouTube Kids）。
- 對帳（每 60 秒，補漏用）：讀電視上的實際狀態，與「該不該開」不一致才下指令。
- 所有狀態變更逐一處理（同一時間只處理一件），避免快慢指令互相覆蓋。
- 時鐘：主機開機後系統時間尚未網路校時 → 一律當未授權（鎖）。

| 需求規則 | 怎麼達成 | 等級 |
|---|---|---|
| 預設鎖定、大人也要授權 | 沒有有效到期時間就是鎖 | 設計；待驗 |
| 從核准起算、不暫停 | 到期時間是絕對時間，跟電視開關、切 App 無關 | 設計 |
| 到期自動關閉播放中的 YouTube | force-stop＋停用 | 文件（adb）；播放中被關的實際畫面待驗 |
| 不自動續期 | 只有家長再按才會有新的到期時間 | 設計；待驗 |
| 重開機不重置 | 停用狀態存在電視系統、到期時間存在主機檔案 | 文件（disable 跨重開機）；本機待驗 |
| 孩子進設定手動「啟用」 | 最多約 60 秒後被對帳停回 | 待驗（Owner 裁定：擋得住一般使用即可） |
| 切換 Google 帳號 | 停用作用在 user 0 的套件狀態；帳號切換與其他使用者情況 | 待驗 |
| 媽媽看 Netflix／4gTV／Disney+ | 只動 YouTube 套件 | 設計目標；每種狀態下都要實測 |

**Home Assistant 為什麼不用**：HA 的 timer 在 HA 停機期間到期不會補觸發（R3 引官方文件），最後仍要自己寫補鎖；為一顆按鈕多維護一套系統不划算。Owner 之後若本來就要跑 HA，可再搬。
建置與維護成本待實作後評估，不預先承諾行數。

### 失效時的行為（照實寫）
| 情況 | 會發生什麼 |
|---|---|
| 鎖定中，主機或電視連線中斷 | 最後一次確認是鎖定；中斷期間實際狀態未知（例如 OTA 或手動啟用）。恢復連線後先讀狀態，該鎖就鎖 |
| 授權中，主機掛掉／電視斷網／adb 連不上，且跨過到期時間 | **YouTube 會繼續可看，直到重新連上才補鎖**。這段無法保證準時鎖定 |
| 主機斷電 | 沒有即時通知（不另設監測）；iPhone「查狀態」會顯示連不上或上次成功對帳時間 |
| 電視恢復原廠 | adb 授權消失，服務連不上 → 查狀態顯示失聯；已知風險，不處理 |

### 各入口（每項都要實測後填「擋住／擋不住（列風險）／不適用」）
原生 YouTube App、遙控器 YouTube 鍵、語音開 YouTube、其他 App 的 YouTube 連結、YouTube Kids（先確認本機有沒有）、iPhone 投放（**主要風險**：預期停用後投放失敗，待驗）、瀏覽器 youtube.com（先盤點本機有無瀏覽器與家人用途，要停用須 Owner 同意）、既有第三方 YouTube 播放器（先盤點，逐一由 Owner 決定）。
不做自動停用新裝 App 的功能。

### 前置需求（皆須 Owner 同意後才做）
1. 電視開啟開發者選項＋網路偵錯，首次按「一律允許」主機的金鑰。這是設定變更。
2. 電視需要固定位址讓主機連得到：M9 DHCP 保留，或其他現場可行方式。
3. 家中 iPhone 操作先做；確定要在外面操作再加 Tailscale（個人免費）。adb 與服務埠不對外開放。
4. 服務只裝在 Linux 小主機；移回前 Mac 只做步驟 1～3 的手動測試，不跑服務。

## 4. 最小可行執行計畫

順序：前置 → 健檢 → YouTube 閘門 → 瘦身（Mac 手動，可與等主機並行）→ 服務（Linux 主機回來後）。
每一步動手前都要 Owner 授權；Owner 可一次授權多步。涉及目前禁止事項（ADB 變更、路由器、開工單）一律先問。

**步驟 0：前置設定（Owner 授權後）**
- 電視開發者選項＋網路偵錯、首次金鑰授權；電視固定位址。
- 驗收：Mac 執行 `adb connect <電視IP>:5555` 後 `adb devices` 顯示 `device`（不是 `unauthorized`／`offline`）。

**步驟 1：唯讀健檢（不改任何設定）**
- 情境固定：A＝剛開機閒置 2 分鐘；B＝正常使用 2 小時後。各跑一次：`getprop ro.build.fingerprint`、`cat /proc/meminfo`、`dumpsys meminfo`、`df -h /data`、`dumpsys cpuinfo`、`top -n 1`、`dumpsys diskstats`、`pm list packages -f`、`pm list packages -d`、`cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN`。
- 另記錄操作基準（碼錶）：按 Home 到首頁可操作、首頁開 YouTube 到可選片、首頁開 Netflix 到可選片，各量 3 次；一週內卡死需重開的次數（家人回報）。
- 五個 App 基準：各自是否已安裝、能否播放；HBO Max 若裝不了，記錄 Play 商店顯示的訊息。
- 驗收：每個指令有輸出或標「不支援」；產出本機套件清單、RAM／儲存實際數值與 /data 可用量（門檻依 AOSP「5% 與 500 MB 取較低」並註明 OEM 可能不同）。缺的資料標「未取得」，不得標成全部完成。
- 結果只回報，不改設定；清空間、撤麥克風等改動另列待授權。

**步驟 2：YouTube 鎖定閘門（手動 adb，Mac）**
- 先記錄 YouTube／YouTube Kids 原始狀態（`pm list packages -d | grep youtube`）。
- 停用 `com.google.android.youtube.tv` 後逐項測並記錄：首頁圖示、遙控器 YouTube 鍵、語音「播放 YouTube」、iPhone 投放、其他 App 的 YouTube 連結、設定 → 應用程式能否手動「啟用」、Netflix／4gTV／Disney+ 能否播放、電視重開後是否仍停用。
- 模擬到期：YouTube 播放中執行 `am force-stop`＋`pm disable-user`，記錄畫面是否立即停止。
- 重連：電視重開後每 30 秒嘗試 `adb connect` 一次、最多 6 次（3 分鐘）；待機 10 分鐘後同樣嘗試。記錄是否需要人到電視前操作才能連。
- 測完只把本次改過的套件恢復成原始狀態，並確認 YouTube 能正常播放。
- **通過條件**：停用後原生 App、遙控器鍵都打不開 YouTube；播放中停用會停止播放；Netflix／4gTV 正常；重開後仍停用；重開或待機後 3 分鐘內 adb 能自動重連。
- **停止條件**：停用 YouTube 影響其他 App 或系統功能 → 方案 C 停，改評估方案 A。重開後 adb 無法自動重連 → 回報 Owner（鎖定仍安全，但無法遠端開放）。投放或語音仍能播 → 回報 Owner 決定接受為已知漏洞或另想辦法。

**步驟 3：瘦身第一批（Mac 手動）**
- 候選線索 ∩ 本機套件，每次 3～5 個：記錄原始狀態 → 停用 → 重開 → 冒煙測試（步驟 1 中原本可用的 App 都要能播放、HDMI 切換、遙控器 Home／返回／音量／訊號源／YouTube／Netflix 鍵、Wi-Fi、Play 商店開啟、系統設定開啟、首頁顯示）→ 依步驟 1 同情境重量數值與碼錶基準，並截圖首頁前後對照。
- 通過：冒煙測試全過即為「安全通過」；效能有沒有改善另外回報，不設硬門檻。
- 停止條件：任一冒煙項目失敗 → 立即還原本批並停止回報；第一批做完效能沒有明顯改善、仍會卡死 → 停止瘦身，回報 Owner 是否改外接電視盒。

**步驟 3b：換桌面 Projectivy（第一批完成後，可選；Owner 10-29 詢問後加入）**
- 依據：步驟 1 的 `dumpsys meminfo` 看原廠桌面（`com.google.android.tvlauncher` 等，以本機 HOME 查詢結果為準）實際占多少 RAM，以及首頁卡頓程度。
- 3b-1 安裝 Projectivy、用 override 模式（原桌面不停用）→ 首頁只放五個影音 App → 跑冒煙測試＋同情境量測。還原＝解除安裝 Projectivy。
- 3b-2（較高風險，另經 Owner 同意）：若 3b-1 後原桌面仍常駐占大量 RAM，才考慮停用原桌面。前提：Projectivy 已能穩定接手 HOME、重開後不被搶回、遙控器 Home／T 鍵／訊號源正常，且 adb 可連以便還原。
- 停止條件：重開後 HOME 被原廠搶回或卡在空白畫面 → 還原並列為限制。

**步驟 4：時間管理服務（Linux 主機回來、Owner 同意開工單後）**
- 小服務＋systemd 開機自動啟動＋iPhone 捷徑（開放 15／30／60、立即鎖、查狀態）。
- 驗收（全部記錄核准時間、到期時間、實際停止時間）：
  1. 服務首次啟動、到期後：YouTube 都是停用；大人直接開也打不開。
  2. 開放 30 分鐘：確認成功才顯示可看；期間切 Netflix、關電視再開，到期時間不變。
  3. 播放中到期：在到期時間後 60 秒內停止並停用；之後等待兩個對帳週期仍打不開（不自動續期）。
  4. 15／60 分鐘各測一次到期時間正確；立即鎖後打不開；查狀態與電視實際狀態一致；adb 失敗時捷徑不得顯示成功。
  5. 未帶 token、錯誤 token 的請求一律被拒，不改變狀態。
  6. 斷線測試：(a) 鎖定中把電視斷網 5 分鐘再恢復 → 仍鎖定；(b) 授權中斷網並跨過到期時間、恢復後 → 2 分鐘內補鎖，記錄斷線期間是否仍可播；(c) 授權中重開電視 → 開機後到期時間不變、到期照鎖；(d) 主機重開 → 依檔案恢復狀態，系統時間未校時前保持鎖。
  7. 鎖定、授權、到期、重連各狀態下 Netflix、4gTV 都實際播放一次。
  8. 入口表逐項填「擋住／擋不住（列風險）／不適用」。
- 第 1～7 項任何一項沒過＝不通過；第 8 項擋不住的入口列風險，不影響通過。

**全程**：出現開不了機、遙控器失效、HDMI 無訊號、Netflix DRM 錯誤 → 若 adb 仍可連，立即還原最後一批並回報；adb 也連不上 → 停止一切操作回報 Owner，不自行恢復原廠。
